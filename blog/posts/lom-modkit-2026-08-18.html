2026-08-18v1.1.0 · MOD 存档与 Combat/Battle 修复

活侠传lom_modkitv1.1.0save

v1.1.0 主要处理 1.0.1 之后发现的 Combat/Battle 实机问题，并把 MOD 战役存档整理成更接近原版、可以长期使用的流程。Editor、Compiler 与 MortalModHost 版本统一到 1.1.0。

MOD 独立存档

  • 232f8a4 每个 campaign_id 拥有原版风格的 001–020 手动栏位；空栏开始新战役，已有栏位可覆盖或读取。
  • 剧情、自由模式和战斗自动档继续使用同一 MOD 的隔离命名空间；标题页与游戏内读档入口复用原版槽布局，不改变原版读档 UI。
  • 保存/读取同时绑定 MOD、完整包指纹、剧情节点和 Gameplay checkpoint，降低跨包冒名、误读原版槽或恢复到错误战斗的风险。

Combat / Battle 状态修复

  • 修复自动读档后回合数递增、战斗数值变化、赵活生命缓存重复叠加和第 0 回合启动等问题。
  • 支持 player_* 与 player_talents 覆盖本场 Combat；生命值先采用原版体力、属性和被动的最终结算，再叠加 player_max_health，避免覆盖原版增益。
  • Battle 支持可验证的具名角色 roster、人数和生命配置；Combat/Battle 结果继续绑定真实原版 win/lose 结果。

剧情恢复与编辑器

  • 跨章节 next_script 和剧情自动存档读取时保留 MOD 自定义背景，避免恢复后变黑或被 Host 清空。
  • Combat/Battle 表单、校验、代码生成和字段说明同步覆盖玩家基准属性、天赋、战斗 roster 与生命配置。
  • Showcase3 更新为 62 节点实机验收包，覆盖 Combat/Battle、背景、自动存档和新生命规则。

质量与仓库整理

  • 增加存档隔离、Gameplay checkpoint、战斗数值与来源包切换的回归测试；Runtime Release、SmokeTest、Gameplay API 校验、冻结编辑器自检和完整测试矩阵通过。
  • e4e37f1 发布后清理旧 samples 与 legacy release docs，减少仓库里已经失效的历史产物。

升级提示

旧 showcase3 自动档可能还保存旧的 player_max_health 或空背景。升级 1.1.0 后，建议从当前 MOD 的空白手动栏重新开始一次战役，再生成新的剧情/战斗自动档。
