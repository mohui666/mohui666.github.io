活侠传 lom_modkit 开发日志 BepInEx PySide6

lom_modkit 是《活侠传》的可视化剧情 Mod 工具：图形编辑器编排剧情，编译成游戏原生 Lua，打成 .lommod 包，由 BepInEx 插件在游戏内演出。这篇日志按 commit 历史复盘第一个开发周期（2026-08-12 → 08-15）：36 次提交、604 个文件、+78,788/-5,004 行，终点是 v0.6.0 Windows 发行包。

1. 起点：一个提交吃下 v3 全机制（08-12）

仓库的第一个提交 044d8b0 就是「v3 全机制：38 节点编译器 + 编辑器汉化 + 战役模式插件 + 预览素材管线」。它不是从空目录长出来的——前置工作是对官方 1814 个剧情脚本的实证分析和游戏反编译（版权原因不公开），先把「官方脚本到底怎么写」摸清，再定包格式契约。

这个起点定了后面所有工作的结构：docs/zh_CN/mod_format.md 是编辑器、编译器、运行时三方共享的契约，任何机制改动先改契约。节点数后来从 38 涨到 43（dim/message/rotate/dayenv 四个高价值节点 + death 等），契约文档同步滚到 v3。

2. 与黑屏作战（08-13，19 次提交）

第二天是排雷日。剧情 Mod 工具最恶劣的失败模式不是报错，是黑屏软锁：Lua 协程一死，画面停住、没有任何提示。一天之内打掉了六个互不相干的根因：

症状根因防线
练武场对话冻结show/say 引用了未登场人物，或角色表情 key 无效 → LoadCharacterPortrait 抛 KeyNotFoundException，协程直接死编译期校验 (character, portrait) 必须落在官方表情表内；写入口自动补登场（见 §3）
切场后背景全黑非纯色场景没走 flowcharts.LoadView(view) 预载背景资产scene 节点编译时强制预载
骰子菜单崩溃（NRE）检查点缺官方元数据（骰子范围/结果带），或选项条数不足dice.check 必须命中 editor_data 的 dice_meta 表，否则编译拒绝
选项菜单冻结choice 用了 Talk/Meet 等自由场景皮肤，纯文本选项触发 BreakOptionButton 越界dialog 锁死 Options
transition 黑幕不解除TransitionIn 盖满黑幕，作者忘了配对的 TransitionOut有 in 无 out 编译器警告
F5 中途试玩黑屏从剧情中间进入时，台上人物/场景状态不存在试玩包自动补舞台状态前导（场景、站位、表情、朝向）

这一天还有两个长期方向落地：story_api（AI 受控写入口，525512f）和编辑器的液态玻璃 UI + PyInstaller 双入口打包（828dbc4）。前者让 AI 代理可以安全地构建剧情，后者让工具脱离 Python 环境分发。

3. 把坑写进工具，而不是写进文档

排雷的产出物不只是修复，而是一套防线哲学：已知坑全部由工具强制拦截，不靠作者自觉。规则进了三层：

  1. 写入口（story_api / 编辑器共用）：AI 不直接手写 story JSON 或 Lua，一切构建走受控 API。未知字段一律拒绝，非法值当场 ValueError。
  2. 登场防线（6075001）：动作类节点的目标人物在前面未登场/已退场时，自动在它前面插入 show；更新节点导致人物退场时连入边跳转一起重定向。体检模块对多路径汇合做图级兜底。
  3. 编译期（lomc）：校验错误 + 非致命警告（-- lomc 警告： 注释嵌进 Lua 头部），导出前 F6 体检再扫一遍断路、不可达步骤、死循环、占位文本。

效果体现在样例质量上：snack_case《点心大盗疑案》战役剧情线（29cc0a7）和 showcase2 全节点演示都是在这套防线下构建的，没有手写过一行 Lua。

4. v0.6.0：从能用到敢发（08-14）

3d28acd 收了第一个发行版。编辑器信息架构重排（菜单管低频、工具栏只留试玩/导出）、已读重置、fadeout 等待，以及一个折腾最久的：Steam 普通启动加载 BepInEx。Steam 会把 DOORSTOP_INITIALIZED 等环境变量带进游戏进程，Doorstop 引导在 fopen(target_assembly) 之前就被短路——这个根因和修补单独写过一篇：Steam 环境下 Doorstop 引导被 DOORSTOP_INITIALIZED 短路，补丁已提给上游（UnityDoorstop PR #109）。

5. 用户内容：音频 → 语音 → 自定义立绘（08-14 → 08-15）

发行之后立刻开始做用户内容库，目标是把 lom_modkit 从「剧情编辑器」往「用户内容创作工具链」推：

  1. 自定义音频（9bbbc5d）：本机导入 .ogg/.wav，剧情只存 user:mohui.battle 这样的稳定引用，导出只打包实际引用。一个硬问题：游戏主混音是 Wwise，Unity AudioSource 播自定义音频经常无声，最后改走 Windows waveOut 流式播放（9364cf0）。
  2. 对白语音（9bfc60a）：say 节点加可选 voice 字段，逐句配音，独立通道不被音效/StopMusic 打断。
  3. 自定义立绘角色 v1（4ebccf2）：PNG 立绘导入即成为可登场人物。中间修了两个显示 bug：立绘铺白幕（bc2408a）、顶满舞台（6d6511d，改为按站位槽缩放）。

6. 多语言与文档产品化（08-15）

最后一天全在打磨「别人能不能看懂」：

  • 编辑器界面四语言（简中/繁中/日语/韩语），游戏名词走 LoM-wiki、缺项回退官方解包语言表；游戏内 Mod 菜单跟随游戏语言（56e8609）。步骤支持 F2 重命名（同步全部跳转引用）与拖动排序。
  • 文档重构为 per-locale 架构：docs/zh_CN/ 权威版 + 三种语言译文，新增文档索引，全部交叉链接修好（5020b60）。
  • README 从「开发者技术说明书」重构成产品化首页：下载按钮、能做什么、玩家向三分钟快速开始、兼容性表、FAQ，开发者内容下沉（89bdf12）。
