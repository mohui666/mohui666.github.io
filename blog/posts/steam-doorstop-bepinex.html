Doorstop · Steam · BepInEx

不提权就不加载

2026-08-14 活侠传 / Legend of Mortal · Unity 2020.3 Mono x86

Doorstop BepInEx Steam

Steam 点「开始」进标题没有「活侠MOD」，F8 没菜单。同一套文件，勾了管理员兼容就能加载。看起来像权限，其实 Doorstop 在进 BepInEx 之前就被掐掉了。

加载链

BepInEx 自己不负责钻进 Unity。顺序是：

Steam → Mortal.exe → Doorstop（游戏目录 version.dll）→ 钩 GetProcAddress → mono_jit_init_version → Doorstop.Entrypoint.Start → BepInEx → MortalModHost

哪一截断了，日志表现不一样：没有新的 doorstop_*.log 是 DLL 没进进程；有 Doorstop 日志但没有新的 BepInEx/LogOutput.log 是引导被跳过。

误判

  • 把 BepInEx 升到 785 / 迁 LTS：#1340、#1331 只是写配置失败别 abort，托管代码还没被叫到。
  • 只改 BepInEx 的 C# 并覆盖 BepInEx.Unity.Mono.Preloader.dll：LogOutput.log 时间戳不动。
  • 只开 ignore_disable_switch：能躲过 DOORSTOP_DISABLE，躲不过后面的 DOORSTOP_INITIALIZED。

三层原因

层现象做法
Steam 塞 DOORSTOP_DISABLE Doorstop 进进程立刻自杀。管理员走 UAC，不继承这份环境。 doorstop_config.ini 里 ignore_disable_switch = true（官方注释本来就是给 Steam 破坏环境隔离用的）
代理 DLL 叫 winhttp.dll overlay / steamclient 先加载系统 winhttp，游戏目录那份插不进去。 Doorstop 4.x 同时导出 VERSION + WinHttp，改名为 version.dll。UnityPlayer 静态导入 VERSION.dll。
继承了 DOORSTOP_INITIALIZED 钩子装上、Mono 进了，日志写 DOORSTOP_INITIALIZED is set! Skipping! 开了 ignore 开关时清掉继承变量；本进程是否引导过用静态标志，不信环境变量。

真正钉死第三层的是 16:27 这份 verbose 日志（节选见附件）：

CONFIG: General.ignore_disable_switch = true
Got mono_jit_init_version at 097B0000
Starting mono domain "Unity Root Domain"
DOORSTOP_INITIALIZED is set! Skipping!

同类问题上游已有 UnityDoorstop#73（游戏自己重启也会继承这两个变量）。

改了哪些代码

1. UnityDoorstop（真正修好的地方）

上游 PR：NeighTools/UnityDoorstop#109

文件改什么
src/bootstrap.c · mono_doorstop_bootstrap 若 ignore_disabled_env 为真，不因继承的 DOORSTOP_INITIALIZED 直接 return；本进程用静态 doorstop_bootstrapped 防重入。
src/windows/entrypoint.c · DllEntry 在 load_config() 之后 SetEnvironmentVariableW(L"DOORSTOP_INITIALIZED", NULL) 以及 DOORSTOP_DISABLE。
src/nix/entrypoint.c · doorstop_ctor 同样 unsetenv，Linux/mac Steam 同一类泄漏。

本地游戏用的是这份源码编出来的 x86 doorstop.dll，复制成游戏根目录 version.dll。本机副本在 lom_modkit/third_party/UnityDoorstop/。

2. 游戏目录配置（不改源码也能先试前两层）

路径内容
LegendOfMortal/doorstop_config.ini enabled = true，ignore_disable_switch = true，target_assembly = BepInEx\core\BepInEx.Unity.Mono.Preloader.dll
LegendOfMortal/version.dll Doorstop 代理。不要同时再放一份抢系统的 winhttp.dll。
LegendOfMortal/version_alt.dll 系统 VERSION.dll 的副本，给 load_proxy 转发真实导出。

3. BepInEx 仓库（发行向，不是这次断点）

本地分支 third_party/BepInEx 的 steam-nonadmin-load：默认 ini 打开 ignore 开关、Windows 包改打 version.dll。按 BepInEx 的贡献规则，默认改所有游戏要先问，所以没有往 BepInEx 提 PR。

文件改什么
Runtimes/Unity/Doorstop/doorstop_config_mono.ini默认 ignore_disable_switch = true
build/Program.cs · MakeDist WindowsDoorstop 复制为 version.dll 而不是 winhttp.dll

怎么确认修好

  1. Steam 普通点开始，不要管理员。
  2. 新的 doorstop_*.log 里应有 Cleared inherited DOORSTOP_INITIALIZED 和 Opening assembly，不能再停在 Skipping!。
  3. BepInEx/LogOutput.log 时间变成这次启动，出现 BepInEx 6.0.0-be.785 和 MortalModHost。
  4. 标题左下角「活侠MOD」，菜单是 F8。
